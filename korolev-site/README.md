# Королёв Роман Викторович — редакция по новым правкам заказчика

Сохранён стек текущего проекта: Flask + Jinja + SQLAlchemy / SQLite. Внесены правки из переписки и тексты из четырёх Word-файлов. Итоговый состав и пояснения — в `ИТОГОВАЯ_ВЕРСИЯ.md`. Все присланные сканы и логотипы включены.

## Быстрый просмотр

Откройте `index.html` обычным браузером — это автономный снимок актуальных Flask-шаблонов с встроенными стилями и изображениями. Ссылки на услуги, три типа дел, профиль и аттестаты работают без сервера. Это только просмотр, панель управления в него не встроена.

Для дальнейшей разработки главным источником является Flask-приложение, а не ручная правка автономного `index.html`. После изменений снимок нужно пересобрать из шаблонов командой `python build_preview.py` (после установки зависимостей). Предпросмотр не следует публиковать вместо приложения: он использует внутреннюю маршрутизацию, а SEO подготовлено для настоящих серверных страниц.

## Локальный запуск

Python 3.11–3.13. В терминале из папки проекта:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py init-admin
python main.py
```

На Windows активация: `.venv\Scripts\activate`.

`init-admin` создаёт случайный SECRET_KEY в `.env` и запрашивает пароль скрытым вводом. Минимум 16 символов. Пароля по умолчанию нет; создавать его через публичный сайт нельзя.

Сайт: `http://127.0.0.1:5001`. Панель: `http://127.0.0.1:5001/admin`.

Локально `.env` содержит `LOCAL_PREVIEW=1`: индексация запрещена, cookie работает по HTTP. Если SECRET_KEY не задан или слишком короткий, приложение намеренно откажется запускаться. Файл `.env` не включён в архив. Переменные окружения можно задать без `.env`; `python-dotenv` нужен именно для автоматического чтения файла.

## Что и где редактировать

- `defaults.json` — исходные настройки, ФИО, тексты первого экрана, контакты, домен, стаж, комментарий к аттестатам.
- `content.json` — исходные услуги, пояснения по типам дел, клиенты, организации опыта, партнёры, гарантии и отзывы.
- `templates/` — структура страниц.
- `static/css/style.css` — сохранённая светлая стилистика, увеличенная типографика, адаптивность. Основные цвета в `:root`.
- `static/js/site.js` — меню, просмотр сканов, цветовое выделение фамилии.
- `static/img/portrait.webp` — оптимизированное фото с предварительно обработанным фоном. Оригинальные черты лица не генерировались.
- `static/brand/` — утверждённый логотип заказчика в WebP/PNG и favicon.
- `static/img/documents/` — оптимизированные сканы и отдельные облегчённые миниатюры.
- `static/img/organizations/` — полученные логотипы организаций.
- `source-materials/` — присланные оригиналы для дальнейшей работы; не публикуйте эту папку отдельной статической раздачей.
- `storage/site.db` — настройки и технический учёт попыток входа. Создаётся при запуске.
- `storage/password_hash.txt` — хеш пароля, закрытый от публичной раздачи.
- `storage/content.json` — пользовательские правки контента; появляется после сохранения в панели. Имеет приоритет над исходным `content.json`.

**Панель:** основные тексты и контакты — обычные поля. Для добавления и удаления партнёров есть отдельный раздел «Сотрудничество — добавить партнёра»: название, необязательные описание и логотип. Услуги и остальные разделы — JSON-редактор с проверкой. Это не визуальный drag-and-drop конструктор. Можно загружать портрет, сканы, логотипы организаций, удалять опубликованные документы, включать реальные отзывы. Логотипы организаций при загрузке автоматически приводятся к единому монохромному формату. Для логотипов лучше использовать прозрачный либо белый фон. Логотипы SVG лучше передать разработчику для проверки и конвертации; публичная загрузка SVG намеренно не разрешена. Для PNG с прозрачностью фон портрета и документов приводится к светлой гамме сайта; логотипы нормализуются отдельно.

Для выделения строки фамилии на справочнике у соответствующего документа:

```json
"highlights": [[15, 40, 35, 3]]
```

Это x, y, ширина, высота в процентах от скана. В полученных справочниках оставлены отдельные страницы 338 и 184; координаты фамилии уже заданы; при замене скана их нужно пересчитать. Исходный документ не ретушируется. Удаление документа из панели убирает публикацию, но не очищает файл и резервные копии автоматически.

## Нет формы обратной связи

Форма, её включение в панели и сохранение новых обращений убраны по окончательному указанию заказчика. `/contact` отвечает 410 и не пишет в базу. Старые модели таблиц из исходного проекта оставлены для совместимости структуры, но приложение не читает и не создаёт клиентские обращения. Если на настоящем сервере уже есть старые заявки, их хранение/удаление отдельно решает владелец — этот комплект не удаляет чужую production-базу.

Не нужно вводить реквизиты оператора лишь для включения формы: формы здесь нет. Это не отменяет возможные обязанности владельца при работе через email, мессенджеры и серверные журналы.

## Публикация

Хостинг с Python / Gunicorn либо VPS. Перед размещением:

1. Подтвердите финальные тексты и допустимость публикации реквизитов на сканах. Логотип, палитра и присланные материалы уже включены.
2. Проверьте домен и сертификат. В `.json` исходный основной адрес — `https://korolev.expert`. Сертификат из переписки заказан для `www.korolev.expert`; факт выпуска и покрытие обоих имён не проверены.
3. Сгенерируйте секреты и пароль на настоящем сервере, не используйте тестовые значения.
4. Установите `LOCAL_PREVIEW=0`. Этот режим предполагает HTTPS, включает Secure-cookie. Открытый HTTP с production-cookie не подходит для входа.
5. Запускайте Gunicorn за HTTPS reverse proxy от отдельного непривилегированного пользователя. Не используйте `python main.py` как production-сервер.
6. Откройте наружу только nginx/HTTPS. Gunicorn по умолчанию слушает `127.0.0.1:5001`. Настройте редирект HTTP → HTTPS и альтернативного www/non-www → основной адрес.
7. Не раздавайте корневую папку приложения через nginx. В частности, `.env`, SQLite, хеш пароля, `storage/` не должны быть публичными.
8. Резервируйте `storage/` и `static/img/uploads/`. Это постоянные данные; эфемерный диск не подходит. Один процесс записи рекомендован для JSON-редактора.
9. Проверьте `/sitemap.xml`, `/robots.txt`, canonical. После публикации добавьте сайт в Яндекс Вебмастер и Google Search Console. Гарантий поисковых позиций нет.

Запуск:

```bash
gunicorn -c gunicorn.conf.py wsgi:app
```

В `.env` уже должен быть валидный SECRET_KEY и `LOCAL_PREVIEW=0`. Панель поддерживает до 6 неудачных попыток входа с адреса за 15 минут; счётчик хранится в SQLite и не сбрасывается удалением cookie. За reverse proxy дополнительно настройте лимит nginx; приложение намеренно не доверяет произвольному `X-Forwarded-For`.

### Docker

Dockerfile и compose включены, но Docker-сборка в этой среде не выполнялась. Для запуска подготовьте `.env` с production-настройками. На первом запуске можно временно задать `ADMIN_PASSWORD` от 16 символов: если хеша ещё нет, он будет создан. После настройки удалите эту переменную из окружения; хеш остаётся в постоянном томе.

```bash
docker compose up -d --build
```

Compose открывает порт только на localhost и создаёт постоянные тома для настроек и загрузок. HTTPS и DNS настраиваются отдельно.

## Изображения и оформление

Использован выбранный заказчиком JPEG-логотип, а не прежние реконструкции. Фон очищен, рисунок и рельеф сохранены. Интерфейс использует точные sRGB-цвета #4B453F и #C2B19F. Аттестаты, справочники и логотипы организаций включены из присланных файлов; отдельные миниатюры уменьшают начальную загрузку, полные сканы открываются по нажатию.

Подробности, включая уточнение издателя аттестатов и решение противоречивых требований, — в `ИТОГОВАЯ_ВЕРСИЯ.md`. Результаты локальных проверок — в `ПРОВЕРКИ.md`.

## Новая редакция по списку заказчика

- Шапка по присланному скриншоту: 66 px на широком экране, логотип слева, меню и контакты в одну строку. На телефоне — адаптивное меню. Меню: Услуги → Клиенты → Опыт → Квалификация → Сотрудничество → Гарантии.
- Основные разделы остаются секциями главной; квалификация и профиль имеют отдельные страницы. Существующие ссылки на страницы услуг сохранены.
- Цветные три кнопки: Уголовные дела → Гражданские споры → Арбитраж. Под фото фамилия и имя с отчеством разделены; круглая ссылка 20+ ведёт к опыту.
- Клиенты: шесть карточек, адвокатские и экспертные бюро разделены.
- Уточнены организация РЕГИОН и все присланные должности. Удалены «Практический контекст» и лишние вводные тексты.
- Сохранены оригиналы цветных логотипов; опубликованы нормализованные монохромные версии в одинаковых графических полях, без растяжения пропорций.
- Квалификация разделена на Аттестаты и Справочники. Комментарий к аттестатам не менялся в этой редакции. Сканы увеличиваются. Вместо разворотов показываются отдельные страницы с фамилией; исходные развороты сохранены в комплекте.
- В подвале три столбца: логотип и 2024–2026 ©; ФИО, статус и четыре миниатюры (два аттестата и две обложки); телефон и почта. Telegram/WhatsApp не выдуманы: ссылки появляются только после заполнения соответствующих полей в панели.
- Интерфейсные тексты — не менее 16 px, основной текст — 18 px. Содержимое настоящих сканов не перерисовывалось: для него предусмотрено увеличение.
- Публичные тексты услуг и юридические оговорки предыдущей редакции не переписывались, кроме прямо запрошенных названий и изменений. Эта работа не является юридической проверкой.

Дополнительная последняя правка: убрана декоративная нумерация карточек услуг, клиентов, опыта, гарантий и страниц услуг. Убран счётчик порядкового номера в просмотре документов; навигация стрелками сохранена. Содержательные числа (стаж, телефон, годы, типы аттестатов, страницы справочников и статьи УК) сохранены.

Последняя правка «Арбитража»: в начале страницы два самостоятельных крупных блока «Клиентам банков» и «Банкам». Первый вопрос — об утрате денег или финансовых активов, второй — о споре с контрагентом. Нумерация не используется.

Уточнение цветового выделения вопросов в «Арбитраже»: блок для клиентов банков — светлый бежевый с тёмным текстом, блок для банков — #4B453F со светлым текстом #F6F3EF и акцентом #C2B19F.
